# Legacy Infrastructure

> Documentation for legacy infrastructure components retained for historical reference.

---

# Overview

This directory contains documentation and configuration artifacts related to legacy infrastructure that are no longer part of the active Phantom Ecosystem architecture.

These resources are preserved solely for historical reference, migration purposes, or compatibility with older deployments.

---

# Purpose

The purpose of this directory is to archive infrastructure components that have been superseded by the current deployment model while maintaining a record of previous architectural decisions.

Legacy resources are **not** considered part of the active ecosystem.

---

# Current Status

The Phantom Ecosystem currently operates as a single Docker Compose deployment.

The legacy infrastructure documented in this directory is no longer used in production.

---

# Archived Components

Examples of legacy resources may include:

- Historical service definitions
- Previous deployment configurations
- Migration artifacts
- Deprecated startup scripts
- Legacy system service files

These files are retained for reference only.

---

# Oracle Infrastructure

Earlier iterations of the Phantom Ecosystem were deployed on Oracle Cloud Infrastructure (OCI).

Examples include:

- `phantom_bot.service`
- Previous systemd service definitions
- OCI-specific deployment assets

These resources are no longer part of the current deployment architecture.

---

# Design Philosophy

Historical infrastructure is preserved to document the evolution of the ecosystem and to provide context for architectural decisions.

Legacy resources should not be used as a reference for new deployments.

---

# Public Repository Scope

This directory is provided for historical documentation purposes only.

It does not represent the recommended deployment model.

The current deployment architecture is documented separately.
